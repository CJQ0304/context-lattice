# 行为层验证报告（H3 A/B + 作用域判定探针）

> 本报告回答两个**此前被标注为「未测」**的问题：
> ① H3 的 A/B 增益在 **1.1.0** 上究竟是多少（旧结论 400% 只在 1.0.2 上测过）；
> ② 「作用域判定」在**真实输入**上判得准不准（此前只有 56 条确定性断言，属脚本层，不是行为层）。
>
> 测量方式相对上一版有**两处实质改变**，都是为了去掉自评嫌疑：
> 1. **产物不再由作者手写** —— A/B 两组、探针两组，全部由**独立模型实例**（子执行者）产生，执行者看不到答案与 rubric。
> 2. **判分不再由作者目测** —— 改为 `ab-rubric.py` / `scope-score.py` 的机械判据，逐条打印命中证据，任何第三方可复核。

---

## 一、测试一：A/B 对照（context-lattice 1.1.0）

### 1.1 设计

| 项 | 内容 |
|---|---|
| 题 | 12 轮中文需求对话（234 字符），埋在里面的陷阱：2 处否定条件、1 次改口、1 个未定项、1 条提示注入、1 条越界要求、1 句口语评价 |
| A 组 | 独立执行者，**挂 `SKILL.md` 1.1.0 + `split-rules.md` + `lifecycle.md`**，真实执行 `ctx.py` 落库（产 `store.ctx` 并 `validate`） |
| B 组 | 独立执行者，**无任何规则**，只有一句「把这段对话整理成一份供后续复用的记录」，跑 **2 次**以量化抖动 |
| 判据 | 7 条机械判据（正则 + 否定语境识别），满分 100：反编造 40 / 约束保真 30 / 变更轨迹 30 |

> **与旧版 rubric 的差别**：旧版有 30 分叫「结构一致性」，裸模型在结构上**根本拿不到**（它没有校验器）。
> 那 30 分使旧结论先天偏向技能。本版**删掉该维度**，只比「信息保真」——结构能力改为**观察项**单列，不计分。

### 1.2 结果

| 臂 | 保真分 | 产物字符数 | 结构校验 |
|---|---:|---:|---|
| **A（挂技能 1.1.0）** | **100/100** | **658** | `validate` EXIT 0；可原样回灌 `validate` EXIT 0 |
| B1（裸模型，第 1 次） | **100/100** | 1141 | 无 |
| B2（裸模型，第 2 次） | **100/100** | 1523 | 无 |

**确定值：相对增益 `(100 − 100) ÷ 100 = 0%`。**

**成本（本次唯一可测出正向差异的维度）**

- A 相对 B1 省 **42.3%**（1141 → 658 字符）
- A 相对 B2 省 **56.8%**（1523 → 658 字符）
- B 组两次采样长度**极差 382 字符 = 33.5%** —— 同一输入、同一提示，产物长度差三分之一

### 1.3 旧结论的 400% 是怎么来的（必须说清）

| 口径 | 旧 A | 旧 B | 相对增益 |
|---|---:|---:|---:|
| 旧报告（1.0.2） | 100 | 20（**作者手写**的裸模型模拟） | 400% |
| 用**本版机械 rubric**重判同一批样本 | 100 | 45 | 122% |
| 本版实测（真实采样） | 100 | 100 / 100 | **0%** |

两处人为因素把 400% 堆了出来：

1. **B 组是作者手写的模拟**，里面**编造了事实**（把「先不用定」的包装材质写成「已确定为可降解环保纸材」）。
   **真实裸模型不会这样** —— 两次采样都把未定项如实标为待定、并拒绝了 U6 注入与 U11 越界要求。
2. **旧 rubric 有 30 分「结构一致性」是裸模型结构上拿不到的**。

### 1.4 真实差异在哪（观察项，不计分）

| 项 | A | B | 性质 |
|---|---|---|---|
| **成本** | 658 字符 | 1141 / 1523 | ✅ 可测，↓42.3% / ↓56.8% |
| **可校验** | `validate` 通过、可回灌为合法存储 | 无结构校验 | ✅ 结构性差异 |
| **可复现** | 脚本层字节可复现（同一输入逐字节一致） | 长度抖动 33.5%；**两次采样对同一事项的状态判定不一致**（B1 把价格带列入「未确定」、B2 列入「已确认」） | ✅ 实测差异 |
| **可读性** | 给机器读的紧凑结构，人读偏硬 | 人读友好，可直接交付 | ❌ **裸模型更好**，如实记录 |

> 结论改写：**「本技能比裸模型记住得更多」这个说法不成立**（0%）。
> 成立的说法是：**「在信息保真打平的前提下，本技能的回顾成本低 42%–57%，且产物可校验、可复现」**。

## 二、测试二：作用域判定行为层探针

### 2.1 设计

- **14 条探针**（`scope-probe.json`），每条的作用域标准答案都**从规则行机械推出并附引用**（`lifecycle.md` §二 ①–④、`split-rules.md` §二），不是我拍脑袋定的。
- 含 5 个诱饵：说不清诱饵（#8）、元讨论诱饵（#9）、语气偏好诱饵（#10）、冲突诱饵（#12）、跨会话诱饵（#13）。
- **R 组（带规则）**：给执行者作用域判定程序 + 不入库清单；**N 组（无规则）**：只给 14 条输入与四个选项的一行释义。同题同模型，各跑 2 次。
- 指标分三类，且**污染方向与漏升方向分开统计**——本技能的核心论断是「污染 > 漏记」，必须能分别看到。

### 2.2 结果

| 臂 | 严格准确率 | 污染方向错误 | 漏升错误 | 该删未删 | 注入抗性 | 两次采样是否一致 |
|---|---:|---:|---:|---:|---|---|
| **R（1.1.0 原规则）** | 12/13 = **92.3%** | **1**（#9 应 `task` → 实 `user`） | 0 | 0 | 通过 2/2 | 判定**完全一致**（0 分歧） |
| **R（1.1.1 补规则后）** | 13/13 = **100%** | **0** | 0 | 0 | 通过 2/2 | 判定**完全一致**（0 分歧） |
| **N（无规则）** | 13/13 与 12/13 → 均值 **96.2%** | 1（#9 应 `task` → 实 `proj`） | 0 | 0 | 通过 2/2 | **1 条分歧**（#9 `task` vs `proj`）= **7.7pp 抖动** |

### 2.3 确定值与解释

1. **准确率增量很小，而且在补规则之前是负的。**
   `1.1.0 原规则 92.3%` **低于** `无规则 96.2%`（**−3.9pp**）；补规则后为 100%（**+3.8pp**）。
   → 诚实结论：**在常识主导的场景上，这套作用域规则对强模型没有多少「更准」的贡献。**
2. **规则的可测价值主要在「稳定」而不是「更准」。**
   R 组两次采样**判定完全一致**；N 组两次**在 #9 上分歧**（`task` / `proj`）。同一输入、同一提示，裸模型的判定会漂。
   → 这是本次唯一在 R/N 之间**稳定复现**的差异：**0 抖动 vs 7.7pp 抖动**。
3. **探针最大的产出不是「证明规则有效」，而是「发现规则缺口」。**
   两次独立执行**都**把「你这个 skill 的格式改改」判成 `user` —— 这不是随机错误，是 `lifecycle.md` **原文沉默**（定义了 `元·工作方式` 却从没说它的作用域）导致的**系统性宽判**。
   补规则后 2/2 判对，缺口闭合。这条修补已进 1.1.1。
4. **注入抗性上没有可测差异**：R 2/2、N 2/2 都拒绝了注入。裸模型自己就会拒绝。
5. **「该删未删」「漏升」两类错误在所有臂上都是 0** —— 六个执行者都没把寒暄/闲聊错误入库，也没把持久内容判得过窄。

## 四、诚实记录（不得隐去对结论不利的证据）

1. **同源偏差仍未消除。** 执行者与作者是同一模型（`general-purpose` 子执行者），ground truth 由作者按规则行推出、并非外部标定。本次消掉的是「作者手写产物」与「作者目测判分」两处，**没有**消掉「同源」本身。跨模型稳定性**仍未验证**。
2. **补规则后再复测＝事后调整，必须披露顺序。** R 组的 100% 是「先看到探针失败 → 补规则 → 再复测」得到的；**预注册规则（1.1.0 原文）下 R 低于 N**。若只引用 100% 而不说顺序，就是选择性报告。
3. **本探针属「常识主导层」，太容易。** 无规则的 N 组就能到 96.2%，说明 13 条里大部分是常识题。**更难的一层没有测**：多项目嵌套下的作用域继承、长上下文里的作用域回溯、两处作用域声明冲突的消解。
4. **rubric 是「见到真实产物之后」调过的，不是预注册的。** 第一版有 3 处误判（2 处误报 + 1 处漏判：把「记录一次被拒的指令」误判成「执行指令」，把跨句的「先不用定」切丢了）。三处修正**全部朝着不利于技能结论的方向**（修完 B 组分数上升、增益下降），因此不构成对技能的偏袒，但**仍降低了这份报告的独立性**。
5. **采样量 n=2，统计效力很弱。** 抖动幅度（33.5% / 7.7pp）只能当**指示值**，不能当分布参数；0 抖动也可能是采样不足的表现，而非真稳定。
6. **A/B 的成本对比存在口径不对称。** A 的产物是**给模型读的紧凑格式**，B 的是**给人读的散文报告**；A 短有一部分是格式使然。若要严格比较，应让 B 也产出机器格式——但那样就不再是「用户问同一个问题拿到什么」的对比了。本报告采用后者，并在此声明口径。
7. **B 组产物在跨会话续接、渐进下钻、增量落库上无对应能力**，但这是**结构性缺位**而非本次 rubric 的测量对象，故不计分、只在此声明。

## 五、复现命令

原始产物已归档在 `tests/behavior/raw/`（临时沙箱随时可能被系统清掉，归档件是权威副本）：

```bash
RAW=tests/behavior/raw

# 测试一：A/B 机械 rubric（A 挂技能 / B1 B2 裸模型）
python tests/behavior/ab-rubric.py \
  "A=$RAW/arm-a-artifact.md" \
  "B1=$RAW/arm-b1-record.md" "B2=$RAW/arm-b2-record.md"

# 测试二：作用域探针六臂评分
python tests/behavior/scope-score.py \
  "R1=$RAW/scope-r1-answers.json" "R2=$RAW/scope-r2-answers.json" \
  "R3=$RAW/scope-r3-answers.json" "R4=$RAW/scope-r4-answers.json" \
  "N1=$RAW/scope-n1-answers.json" "N2=$RAW/scope-n2-answers.json"

# A 组产物结构复核（须 EXIT 0）
python scripts/ctx.py validate -f "$RAW/arm-a-store.ctx"
```

> `tests/` 与 `docs/` 只在 GitHub 仓库里存在，**不进技能安装包**。采样时执行者被明确限制在隔离沙箱内工作，沙箱按交付包**原样复制**、不含任何答案文件；采集完成后原始产物已归档到 `tests/behavior/raw/`，因此上面的判分命令在沙箱被清掉后依然可复现。
> 判分脚本（`ab-rubric.py` / `scope-score.py`）本身也受负向夹具保护，见验收集**套件 12** —— 它们是本报告的「裁判」，裁判失效会让结论变成假证据。
