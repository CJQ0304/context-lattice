# 第 1 轮压力测试报告（关 3 · 行为层）

- **被测**：`context-lattice` 1.0.0
- **环境**：WorkBuddy 单环境（无第二个模型可用）
- **方法**：设计边界用例 → 逐例按 SKILL.md 与 references 作答 → 三级判定（通过 / 部分 / 失守）→ 失守与「部分」写根因 → 修规则
- **口径**：本文的用例设计者是模型本身，存在**同源自评偏差**（同一模型的常识会补上没写的规则）。跨模型稳定性**未验证**，见第 5 节诚实声明。

## 一、用例与判定

→ **不达通过线，必须修规则并复测。** 根因归类见下节。

## 二、失守根因归类

| 根因类 | 涉及用例 | 性质 |
|---|---|---|
| **归因规则缺条**（指代、模糊承诺、口语评价） | 2、5、6 | 全是「输入落在程序已知实例之外，且兜底条款给不出处置」——兜底只保证不丢弃，不保证归对 |
| **义务条款缺失**（对用户的解释与确认义务） | 9 | 只约束了工具行为，没约束话术行为 |
| **流程刚性未松绑** | 14 | 单点问题被完整流程裹挟 |
| **规则字面冲突** | 15 | 「短会话不触发」vs「用户明确要求记忆」无优先级 |

**没有任何一类是「模型偷懒」**——全部是规则没写到。这正是本关要抓的东西。

## 五、残余风险（诚实声明）

1. **同源自评偏差**：用例设计者、被测者、判分者是同一个模型。第 2 轮的满绿**不能**当作跨模型稳定性的证据——按 `expert-skill-qa-loop` 的单环境降级路径，本轮以「覆盖矩阵查空格 + 负向夹具证红 + 重复跑一致性 + 数字带口径」作为等效证据，并**明确声明：本轮为单环境测试，跨模型稳定性未验证**。
2. **用例 15 的阈值仍未量化**：「会话长度阈值」没有具体轮数，因为不同场景差异过大。当前口径是「用户显式要求 > 长度」，这是可判定的；若日后要量化，需另立规则。
3. **未被本关覆盖的**：`prune --compact` 造成的编号漂移对**外部引用**的影响无法在单环境内验证（无外部消费方）。
4. 修正后已**回跑关 2**（`audit.py --profile upload` 与打包模拟解析），结论见 QC 报告——规则改动可能撞坏已过的闸门，此步不可省。
