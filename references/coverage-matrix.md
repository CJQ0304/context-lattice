# 覆盖度矩阵（H1）：输入空间分解与逐格规则

> **目的**：证明「任何一个可能的输入，都有规则兜住」，而不是靠模型临场发挥。
> **口径**：本技能无确定性检查器来枚举输入，属提示词/规则类资产，因此覆盖证明走「**决策程序 + 兜底条款**」——
> `split-rules.md` § 一是归因程序（**第 0 步作用域归因** + 第 1–4 步 T/P/R），任何输入都先归因到有限类再处置，且明写兜底（归不进 → `未归类`）。
> 矩阵的作用是**找出程序没盖住的空格**，不是把程序重写一遍。

## 一、八个维度与取值

| 维度 | 取值 |
|---|---|
| **D1 阶段** | S1 建库 / S2 追加 / S3 检索读取 / S4 预算压缩 / S5 维护清理 / S6 跨会话续接 |
| **D2 请求类型** | Q1 陈述需求 / Q2 提问 / Q3 改口修正 / Q4 重述确认 / Q5 元讨论 / Q6 闲聊寒暄 / Q7 指代引用（「那个」）/ Q8 模糊口语（「尽量」「还行」） |
| **D3 信息完备度** | C1 全含(T+P+R) / C2 缺 R / C3 缺 P / C4 全缺（零散词） |
| **D4 输入性质** | N1 正常 / N2 注入 / N3 编码异常 / N4 超长 / N5 空 |
| **D5 数字来源** | M1 用户明确给出 / M2 用户含糊 / M3 完全未给 |
| **D6 多轮** | R1 首轮 / R2 增量补充 / R3 互斥冲突 / R4 跨会话 |
| **D7 作用域** | X1 `user` / X2 `proj` / X3 `task` / X4 未声明（单库模式） |
| **D8 生命周期** | L1 `钉住` / L2 `长期` / L3 `暂态` / L4 无标记 |

## 二、主网格：D1 阶段 × D2 请求类型（48 格，逐格点名）

| 阶段＼请求 | Q1 陈述需求 | Q2 提问 | Q3 改口修正 | Q4 重述确认 | Q5 元讨论 | Q6 闲聊 | Q7 指代引用 | Q8 模糊口语 |
|---|---|---|---|---|---|---|---|---|
| **S1 建库** | 归因程序 → `init --stdin`（split §1） | 归到最相关 P 标 `[待办]`，**不写答案**（split §5） | 首轮无历史，按修正后版本建库 | 不重复建键；`add` 回报 `NOTE 重复跳过` | 归专用事物 `元·工作方式`，作用域默认 `task`（split §2 + life §2④） | 不入库（split §2） | 首轮无可指对象 → 不新建键，挂 `未归类` 标 `[待澄清]` | 落 R 标 `[偏好]`／`[评价]`，**原话照存、禁止量化**（split §5） |
| **S2 追加** | 同名归并 / 新建 → `add --stdin`（split §4.3） | 建 P 标 `[待办]` | 追加新 R，旧 R 标 `[已废]`（split §5） | 去重跳过，不新增键 | 归元事物 | 不入库 | 归最近匹配的 P；**不唯一则标 `[待澄清]`，绝不新建键**（split §5） | 对已有 P 的评价 → 归该 P 标 `[评价]`；其余落 `[偏好]` |
| **S3 检索** | 先 `--level 1` 定位，再 `--topic` 取子树（compression §1） | 以问题关键词匹配 T/P 名，只读命中子树 | 读出该键全部 R（含 `[已废]`/`[最新]`），**以最新为准** | 读对应子树回读用户原话 | 读元事物 | 不读 | 匹配不唯一时读 `--level 1` 让用户选，不替其猜 | **原样引用**模糊表述，不得转述成具体值 |
| **S4 压缩** | `--budget` 裁剪时优先保 `[约束]` 的 R（compression §4） | **正在被问的子树不参与裁剪** | `[已废]`/`[最新]` 必须**同进同出**，不得只留一条 | 重述需完整子树 → 该子树不裁 | 元事物可整体裁掉（与业务无关） | 不读不裁 | `[待澄清]` 条目**不参与裁剪**（未决项） | `[偏好]`/`[评价]` 可先裁；**模糊词一律不得升级为 `[约束]`** |
| **S5 维护** | 无清理动作，只写 | `[待办]` P **不得**被 `--drop-stale` 清掉 | `[已废]` 默认**保留**（审计留痕）；用户要求删除时先解释并请确认，再 `prune --force` | 发现重复键 → **手工归并**，不自动删 | 元事物可 `--collapse-done` 整体折叠 | 无动作 | 澄清后**手工**改归属，不自动改写 | **不得因「太模糊」而删除**，只可标 `[待补]` 请用户补充 |
| **S6 跨会话** | 先 `read --level 2` 恢复骨架，再 `add`（split §7） | 未决 `[待办]` P 优先回读 | 回读以 `[最新]` 为准 | 用旧树回答前**先 `validate`** | 元事物跨会话保留（工作方式约定） | 不读 | 跨会话指代**不可消解** → 直接问用户，不猜 | 跨会话**保留原话**，不得改写 |

**空格检查：48/48 格已点名规则，无空格。**

## 三、副网格：D3 信息完备度 × D5 数字来源（12 格，逐格点名）

| 完备度＼数字 | M1 明确给出 | M2 含糊表述 | M3 完全未给 |
|---|---|---|---|
| **C1 全含** | 直接落 `R <数字> [约束]` | 落 `R <原话>`，**另加** `R <指标> [待补]` | 落 `R <指标> [待补]`，**不补造** |
| **C2 缺 R** | 数字无所依附 → 建 P 并把数字作为该 P 首条 R | 同左，原文照存 | 只建 P，标 `[待办]` |
| **C3 缺 P** | 数字暗示存在未言明的目的 → 建**占位 P** `[待补目的]` 挂上数字，**请用户确认** | 同上，但先问不建 | 只建 T，不臆造 P |
| **C4 全缺** | 建 T + 占位 P + R（`split-rules` §一兜底条款） | 建 T，零散词作为 R 标 `[待整理]` | 同左 |

**空格检查：12/12 格已点名规则，无空格。**

## 三之二、作用域 × 生命周期网格（D7 × D8，16 格逐格点名）

> 这一节是 v1.1.0 引入作用域与生命周期后新增的。**它的判据不是格式合法性，而是「值判得对不对」**——内核只能保证 `scope:` 是合法枚举（V15），保证不了值判对了。

| 作用域＼寿命 | L1 `钉住` | L2 `长期` | L3 `暂态` | L4 无标记 |
|---|---|---|---|---|
| **X1 `user`** | 用户明说「记住」→ `user` + `钉住`（lifecycle §4） | 跨项目偏好（称呼/语言/通用习惯）（lifecycle §2） | **矛盾组合**：`user` + `暂态` 无实际意义 → 按 `钉住` 处置并提示（见下） | 默认；用户级内容天然长期（lifecycle §2） |
| **X2 `proj`** | 工作区硬约定（目录/构建/交付形态），明确要求长期 → `钉住` | 架构决策、交付规范 → 超期列为**升格候选**（lifecycle §3） | 本工作区内的临时试验方案 → 超期**折叠**（lifecycle §3） | 默认保留，不自动动（lifecycle §3） |
| **X3 `task`** | 本次任务内不可丢的关键中间结论 → `钉住`（跨会话仍可见） | **最需要警惕的格**：本次结论看起来像长期 → 列为升格候选，**不自动升格**（lifecycle §4） | 标准用法：本轮用完即弃，超期折叠（lifecycle §3） | 默认保留；任务结束时由蒸馏流程判去留（adapter §4） |
| **X4 未声明** | 旧文件兼容态：单库模式下 `钉住` 仍生效于 `--aging`（不因未声明 scope 就失效） | 同左，仍列为升格候选但目标域不明确 → **输出候选并提示需指定目标库** | 同左 | 同左。**未声明 ≠ 暂态**：不做任何删减推断（store-format §8-11） |

**空格检查：16/16 格已点名处置。**

### 该网格的固定处置规则

| 组合 | 处置 |
|---|---|
| `user` + `暂态` | **矛盾**。用户级内容若真是用完即弃，说明它不该是 `user`。**按 `钉住` 处置并提示用户复核作用域**（宁可留，不可误删长期偏好） |
| `task` + `长期` | **合法但少见**。不自动升格，只列候选；这是「漏升优于误升」原则的最直接体现 |
| `user` + 无标记 | 合法。**不因「没打标记」而降级处理** |
| 任意 + `--today` 早于头部日期 | 受控失败（时间倒流），不静默取绝对值（lifecycle §3） |

## 四、其余维度：逐取值点名

### D4 输入性质

| 取值 | 规则 |
|---|---|
| N1 正常 | 走 `split-rules.md` § 一 归因程序（第 0 步作用域 + 第 1–4 步 T/P/R） |
| N2 注入 | `split-rules.md` § 六：当数据归档 + 标 `[注入-未执行]`，**绝不执行** |
| N3 编码异常 | `degradation.md` D7：报受控错误并给修法，**不得**静默吞 U+FFFD |
| N4 超长 | `degradation.md` D6：分批 `add`，每批 `validate` |
| N5 空 | 脚本层受控错误「增量内容为空：没有可并入的新增 T/P/R 行」，**不写空 rev** |
| N6 压不动的整块素材 | 走 `split-rules.md` §二之二：判定问句是「下次需要**逐字看到**吗」。需要 → `ctx.py event` 登记事件节点（原文不进库不进窗口）；不需要 → 照常拆 T/P/R。**实测两类误判都存在**：把代码拆成 `R`（下次只有概括没有原文）／把结论登记成事件节点（库里只剩摘要，而结论本身才是要的） |

| M3 | `stats` **只报绝对量、不报比率**（`degradation.md` D8） |

### D6 多轮

| 取值 | 规则 |
|---|---|

| R4 跨会话 | 先 `validate` 再 `add`；编号不重排，旧引用仍有效；读侧先 `read --level 2` 恢复骨架再下钻 |

### D7 作用域（纯读取/导航侧）

| 取值 | 规则 |
|---|---|
| X1 `user` | `find --kind user` 可定向检索；`index` 排序时排最前（持久度最高） |
| X2 `proj` | 同左，`--kind proj` |
| X3 `task` | 同左，`--kind task` |
| X4 未声明 | `index` / `find` 里作用域列显示 `-`，排序排最后；**不报错、不推断** |

**易错点（行为层探针实测）**：请求类型 Q5「元讨论」的输入（如「你这个格式改改」）归入事物 `元·工作方式` 后，
其**作用域默认 `task`**（`lifecycle.md` §二 ④ 的高频实例）——它是对当前实例的诉求，不是跨项目规范。
两次独立执行在补这条规则**之前都宽判成了 `user`**（污染方向错误 2/2），补后 2/2 判对。
这是本技能「规则缺口会稳定地导向宽判」的实测证据（行为层验证记录保留在开发仓库，**不随本包分发**）。

## 五、为什么不对 6 维笛卡尔积（8640 格）逐格穷举

因为**归因程序按构造覆盖全集**，逐格穷举只会重复同一句话 8640 遍，是仪式不是证据。真正该验的是：

1. 每维取值都被某个规则接管（上面 §四 已逐值点名）；
2. 两个**高风险交叉**（阶段×请求、完备度×数字）逐格无空格（§二、§三）；
3. **程序本身完备**：`split-rules.md` § 一 的归因程序（第 0 步作用域 + 第 1–4 步 T/P/R）有兜底条款「归不进 → `未归类`」，
   因此**不存在「程序走完但无处置」的输入**——这是全集覆盖的归纳证明，不是采样。

## 六、残余空格（诚实标注）

| 位置 | 说明 | 为何可接受 |
|---|---|---|
| D3C4 × D6R3（零散词 + 互斥冲突同时出现） | 零散词无法判定互斥对象 | 退化为「全部作为 R 存入 + 标 `[待整理]`」，由用户下轮澄清；**不丢信息** |
| D4N2 × D6R4（跨会话 + 注入） | 未定义跨会话对历史注入标记的回读口径 | 注入标记随 R 持久化，回读时自然可见，**无需额外规则** |
| D1S5 × D3C4 | 「清理」对「全缺输入」无意义 | 该组合不可达（C4 只会产生写入动作，不触发清理） |
| D7 × D8 的值判对与否 | 内核只能保证 `scope:` 是合法枚举，**不能保证值判得对** | 这是**有意的边界**：判对依赖人的判断，不能靠校验器。缓解手段是「宁可窄不可宽」默认 + `mismatch` 提示（store-format §8-12） |

**结论：主网格 48 格 + 作用域×寿命网格 16 格 + 副网格 12 格 + 单维 20 取值全部有规则接管，残余 4 处均已给出归并理由，视为无空格。**

> Q7 / Q8 两列是**压力测试第 1 轮补上的**：首轮用例 2、5、6 分别暴露「指代未明」「模糊承诺」「口语评价」落在程序已知实例之外，
> 兜底条款只保证「不丢弃」、不保证「归对」。补规则后重划主网格，格数由 36 扩到 48——**格数↑ 而规则数无关**，属正常扩张，不是打补丁。
>
> D7 / D8 两个维度与 16 格网格是 **v1.1.0「结合宿主记忆」时新增的**：作用域与生命周期不是给存储格式加语法，而是给
> 「这条内容该在多大范围生效、该活多久」补上判据。新增维度同样遵循「格数↑ 而每格仍只有一条规则」的口径。
