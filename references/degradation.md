# 降级路径：依赖拿不到时怎么办

> 铁律：**不得静默失败，更不得伪造结果**。任何一步做不了，都要明确说出「哪一步没做」以及替代路径。
> 本技能的外部依赖只有两个：**Python 解释器** 与 **可写目录**。

## 一、依赖检测（开工前先跑一遍）

```bash
python scripts/ctx.py --help
```

- `EXIT 0` 打印用法 → 依赖正常，按 `SKILL.md` 正常流程走；
- 报「命令不存在」→ 试 `python3`，再试绝对路径；
- 仍不通 → 进入 § 二 的纯文本降级模式，**并明确告知用户「本次未使用脚本，统计数字不可得」**。

## 二、逐项降级表

| # | 情况 | 检测方式 | 必须这样处置 |
|---|---|---|---|
| D1 | 无 `python` / `python3` | `ctx.py --help` 失败 | 退化为**纯文本模式**：仍按 `store-format.md` 的结构手工维护 `.ctx`，模型充当写入者。**必须声明「本次为纯文本降级，无脚本校验，`stats` 与压缩率不可得」**，绝不报一个编造的压缩率 |
| D2 | 脚本路径找不到 | `glob` 检索 `**/context-lattice/scripts/ctx.py` | 用检索到的绝对路径调用。仍找不到 → 按 D1 降级并说明 |
| D3 | 目标目录不存在 | `save()` 抛「目标目录不存在」 | 先创建目录再重试；**不得**擅自改到别的目录 |
| D4 | 目录不可写 / 文件只读 | `save()` 抛「无法写入」 | 改用 `read` 输出到标准输出，让用户自行保存；**不得**静默丢弃本轮增量 |
| D5 | 用户拒绝落盘 | 用户明说「别写文件」 | 改为**会话内模式**：每轮把完整 `.ctx` 全文贴在回复里，由用户自己维护。明确告知「跨会话不延续」 |
| D6 | 输入超长（单轮数万字） | 调用方自行判断 | 分批 `add`，每批后跑一次 `validate`。**不得**只归档开头、默默丢掉后半 |
| D7 | 文件带 UTF-8 BOM 或编码损坏 | `load()` 抛 BOM / 解码错误 | 报明确错误并给出修法（去 BOM、转 UTF-8）。**不得**用 `errors="replace"` 静默吞掉，那会产出 U+FFFD 污染 |
| D8 | 原始对话长度未知 | 调用方没有原始文本 | `stats` **只报绝对字符数，不报压缩率**。禁止用估算值充当分母 |
| D9 | `--raw-chars` 传了非正数 | `stats` 抛受控错误 | 报错并跳过比率，**不报 `inf` / `nan`** |
| D10 | 已有 `.ctx` 但结构损坏 | `validate` 非 0 | 先展示**带行号的中文定位**，请用户确认修法；**不得**自作主张删除节点 |
| D11 | `prune` 误删风险 | 用户没加 `--force` | 脚本已硬性拒绝。**不得**建议用户绕过 `--force` 保护 |
| D12 | 环境无 bash（纯 Windows 命令行） | 调用方自行判断 | 直接 `python scripts\ctx.py`；heredoc 改为 `--topic/--purpose/--item` 参数式写入（脚本两种入口等价） |
| D13 | 作用域判不出来（拿不准该记 `user` 还是 `task`） | `split-rules.md` 第 0 步三条问句都答不上来 | **一律落 `task`**，不要为了「显得完整」硬升。域判错是记忆污染（错误结论在错误范围生效），比漏记更糟。等它第二次出现再考虑升格 |
| D14 | 索引缺失 / 过期 / 所在目录不可写 | `index` 报目录不存在或写入失败，或索引内容明显陈旧 | **逐库扫描降级**：直接对目标目录递归找 `.ctx` 再做 `find` 式匹配；索引只是加速与导航，**绝不是主干硬依赖**。索引不可写时把内容打到标准输出让用户自行保存，不得静默跳过 |
| D15 | 库目录与头部 `scope:` 声明不一致 | `index` 输出里出现 `mismatch` | 这**不是错误但必须当信号看**：多为「文件被放错地方了」。把它报给用户并给出两种修法（挪目录 / 改声明），**不要习惯性忽略**——放错地方的记忆会在错误的范围里生效 |
| D16 | 用 shell heredoc 传含反斜杠转义的内容 | 写入的文本出现 `\n` 被改成 `/n` 这类串 | **别用 heredoc 传转义内容**（实测 Git Bash 会篡改 Python 源码里的 `\n`，写进 `.ctx` 的就是坏数据）。改用参数式写入，或先写入临时文件再 `--stdin <` 该文件 |
| D17 | `event --src` 指向的文件读不到（不存在 / 无权限 / 巨大 / 不是普通文件） | `event` 抛受控错误 | **必须报错并停下**。不得复制一个截断的副本进库，也不得为一个读不到的源伪造字节数与哈希 —— 「可校验」的全部价值就在于指纹是真的 |
| D18 | 取回事件节点时源已被改写或消失 | `fetch` 输出 `DRIFT` / `MISS`（**非零退出**），或 `STALE-SRC`（仅提示） | **原样把状态报给用户**。`DRIFT` 的内容**不得当原文使用**（它已不是你登记的那份）；`MISS` 时若库里有 `--embed` 副本，可以给副本但必须同时说明**指针已失效**；只是「指针失效」时**不要**说成「取回失败」 |
| D19 | `index` 跳过了坏库（只有 stderr 的 `NOTE`，退出码仍是 0） | 输出里出现「跳过 N 个」 | **不要把退出码 0 当成「全绿」** —— 扫描有跳过时索引是不完整的，必须把跳过计数报给用户，必要时先修坏库再重建索引。退出码 0 在这里表示「扫描本身没崩」，不表示「每个库都被索引了」 |
| D20 | 管道 / 重定向传给 `--stdin` 的字节不是 UTF-8（英文版 Windows 上常见） | `init --stdin` / `add --stdin` 抛「标准输入不是合法 UTF-8」 | **报错并停下，不得落库**。本工具的增量输入一律按 UTF-8 解读；请用户先把文本转成 UTF-8（记事本另存为 UTF-8，或 `iconv -f GBK -t UTF-8`）再重试。**绝不**按系统本地编码去解 —— cp1252 上会抛错，**cp936 上更糟：解成乱码却不报错，乱码会直接写进库**（这正是 D7 在输入侧的对应物：宁可当场报错，也不产出事后查不出来的数据损坏） |

## 三、降级时必须说出口的话

| 场景 | 必须包含的声明 |
|---|---|
| 走了 D1 纯文本降级 | 「本次未运行脚本，`.ctx` 由模型手工维护，**未经结构校验**，压缩率为**未测**」 |
| 走了 D5 会话内模式 | 「本次未落盘，**跨会话不会延续**」 |
| 走了 D6 分批 | 「共分 N 批，每批已 `validate` 通过」 |
| 分母未知 | 「原始字符数未知，**不报压缩率**」 |
| 走了 D13 作用域兜底 | 「这条内容我暂按**本次任务**归档；如果它其实是跨会话/跨项目的约定，请告诉我，我再升到对应作用域」 |
| 走了 D14 逐库扫描降级 | 「**本次未使用索引**，是逐库扫描得到的命中，可能更慢」 |
| 遇到 D15 mismatch | 「有 N 个库的作用域声明与所在目录不一致（文件可能放错地方了），建议核对后再继续」 |
| 遇到 D20 输入非 UTF-8 | 「管道里传的不是 UTF-8 文本，本次**未写入任何内容**；请先转成 UTF-8 再重试（记事本另存为 UTF-8，或 `iconv -f GBK -t UTF-8`）」 |

## 四、禁止事项

- ❌ 用估算值充当压缩率分母；
- ❌ 在脚本跑不通时给出「看起来正常」的示例输出；
- ❌ 为了绕过 `--force` 保护而建议用户手改文件；
- ❌ 在 `validate` 失败时继续写入（先修再写，否则错误会累积）；
- ❌ 「作用域拿不准」时**替用户猜一个更持久的作用域**——猜错了是记忆污染，危害大于漏记；
- ❌ 把索引当成真相：索引与库不一致时**以库为准**，不得用索引内容去覆盖库。
