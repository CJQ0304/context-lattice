# `.ctx` 存储格式规范（v1）

> 本文件是 `scripts/ctx.py` 解析器的**唯一口径来源**。改格式必须同步改解析器并递增 `version`。

## 一、一句话定位

`.ctx` 是**上下文双层键压缩存储**的落盘格式。它与 JSON 的取舍很明确：

| 对比项 | `.ctx` | JSON |
|---|---|---|
| 单节点 token 开销 | 约 6–10 | 约 20–35（键名与引号占大头） |
| 唯一读者是模型 | ✅ 零语法噪音 | ❌ 大量括号引号属纯噪音 |
| 确定性解析 | ✅ 零依赖 | ✅ |
| 供外部工具消费 | 需 `export --format json` | 原生 |

**结论：模型读 `.ctx`，程序读 `export` 出来的 JSON。** 这两者是「源 → 投影」关系，不存在第二份真相。

叶子有两种：**`R` 要求**（文字约定与约束）与 **`E` 事件节点**（压不动的整块素材）。两者落盘都只有一行，读法却不同 ——
`R` 直接读进窗口；`E` 默认**只读摘要**，原文要显式取回（因为原文可能比整份库还大）。

## 二、行语法

```
存储  ::= (注释)* 头部 (注释|顶层行)*
头部  ::= "#CTX 1 | " 日期 " | rev " 整数 " | T" 整数 " P" 整数 " R" 整数
          ( " | E" 整数 )? ( " | scope:" 作用域 )? ( " | view:" 视图标记 )?
作用域 ::= 种类 ( ":" 限定名 )?                 种类 = user | proj | task
视图标记 ::= ( "level" 整数 )? ( "+" "part" )?     两段可单独或同时出现
顶层行 ::= top 行 | 事物行 | 注释
top 行 ::= "top: " 文本                      （最多出现一次，且必须紧跟头部）
事物行 ::= "T" 正整数 " " 名称 (标记)?
目的行 ::= "  P" 正整数 "." 正整数 " " 名称 (标记)?
要求行 ::= "    " "R" " " 内容 (标记)?
事件行 ::= "    E " 摘要 " | src:" 路径 " | bytes:" 非负整数
           " | sha256:" 16 位小写十六进制 (标记)?
标记  ::= " [" 最长 12 字符，内部不得含方括号 "]"
注释  ::= "//" 任意文本                       （解析时忽略，不影响结构）
```

> **头部 = 第一个非注释行**，因此文件开头允许放 `//` 说明横幅（`templates/skeleton.ctx` 即如此）。
> 三个可选段**顺序固定**：`| E<n>` → `| scope:` → `| view:`，且都必须写在计数之后。
> 老库没有 `| E<n>` 段仍可正常读取；但**有事件行却不声明该段，是结构错误**（V17）——
> 没有这条，「声明了 3 个」和「实际有 5 个」就无法区分。
> `view:` 里的 `part` 表示「本视图被裁剪到某个子树」，与头部 `scope:`（记忆作用域）**是两回事**，刻意不同名以免误读。

缩进是**语义的一部分**，必须精确：

| 层级 | 缩进 | 行首标记 | 角色 |
|---|---|---|---|
| 0 | 事物 | `T<n>` | **上层键** |
| 2 | 目的 | `  P<n>.<m>` | **下层键** |
| 4 | 要求·描述 | `    R ` | 叶子链节点（进窗口） |
| 4 | 事件节点 | `    E ` | 原子叶子（**不进窗口**，只留指针与指纹） |

### 二之二、事件节点（`E` 行）

`E` 用来挂**压不动的整块素材**（要逐字改的代码、要逐行核的数据）。它与 `R` 同级（缩进 4 格），挂在某个目的下。

```
    E <摘要> | src:<路径> | bytes:<字节数> | sha256:<16 位小写十六进制>
```

| 字段 | 约束 |
|---|---|
| 摘要 | 非空、**非纯空白**；禁止半角竖线（它是元信息分隔符，需要竖线请用全角｜）；≤200 字符；与名称同样禁止方括号 |
| `src:` | 相对库文件（优先）或绝对路径，统一用 `/` 分隔；**路径里可以含空格**（`src` 用贪婪匹配取到 `bytes:` 之前） |
| `bytes:` | 非负十进制整数，等于原文的**字节数**（不是字符数） |
| `sha256:` | **原文全文** SHA-256 的**前 16 位小写十六进制** |

**原文不进库**：`E` 行只有指针与指纹。默认指针指向库外的原文件；加 `--embed` 才把正文复制到 `<库文件>.atoms/<sha16><扩展名>`（内容寻址，同哈希只存一份）。

**`E` 这个行首标记本身就是原子性标记**，因此不占用行尾标记位 —— `钉住` / `长期` / `暂态` 可以照常加在 `E` 行尾，不存在互斥。

**读与取回**：`read` 默认只输出摘要行，**原文不进视图**；要原文必须显式 `read --fetch` 或 `fetch`。`--fetch` 的输出以 `====` 起首 —— 它不是合法 `.ctx` 行，**误灌会被 `validate` 当场拒绝**（而不是静默写坏库）。

**取回时的四种状态，必须分开看**：

| 状态 | 含义 | 影响退出码 |
|---|---|---|
| `ok` | 取回内容与登记的字节数、哈希都相符 | 否 |
| `DRIFT` | 取回内容与登记不符（来源被改写） | **是** |
| `MISS` | 找不到来源（文件被移走/删除，且没有内嵌副本） | **是** |
| `STALE-SRC` | **取回内容可用**，但来源指针已不再指向同一内容 | 否（只提示） |

最后一行是这套设计里最容易搞错的地方：内嵌副本能让取回成功，但那**不代表指针还指得准**。如果只报「取回成功」，
「可校验」就会退化成「只要有一份副本就永远绿灯」—— 内容被悄悄改写了你也不会知道。所以**内容校验与指针状态必须分开报**。

**事件节点不参与自动老化**：`prune --aging` 与 `--collapse-done` 都不动它（原文不可再生，折叠掉等于把这条路堵死）。
唯一能删的是**显式**标成 `[已废]` 之后走 `--drop-stale`。

## 三、十字链表的落盘归一化

图示的「十字链表」有显式指针：横向 `next`（同层下一个）、纵向 `down`（下一层第一个）。落盘时**归一化为两个隐式信息**，语义等价但更抗损：

| 图上指针 | 落盘载体 | 好处 |
|---|---|---|
| `next`（同级兄弟） | **行序** | 插入/删除只需重排文本，不用回填指针；损坏时不会出现野指针 |
| `down`（下级首节点） | **缩进** | 父子关系由行自身表达，删除父节点时子节点的越级会被 `validate` 直接抓到 |

```
T1 品牌定位            ← 上层键：事物
  P1.1 确定目标人群     ←   down（缩进 2）
    R 25-35 岁新中产    ←     down（缩进 4）
    R 注重健康养生      ←     next（同为缩进 4，行序相接）
  P1.2 确定价格带       ←   next（同为缩进 2，行序相接）
T2 竞品分析            ← next（同为缩进 0，行序相接）
```

## 四、编号规则（关键约束）

- 事物编号 `T<正整数>`，目的编号 `P<事物号>.<序号>`。
- **编号一经分配即不复用、不重排**：删除只置标记（如 `[已废]`），不回收编号；只有显式 `prune --compact` 才会重排，且重排会使外部引用失效，必须由调用方确认。
- 分配算法是**最小未用正整数**（`_next_topic_num` / `_next_purpose_num`），因此同一操作序列必得同一编号 → 可复现。
- 要求行**无编号**，链上位置即身份；去重按归一化文本判等（连续空白折叠为一个空格、首尾去空白）。

## 五、标记体系（可选的语义标签）

标记写在行尾的 ` [xxx]`，是压缩策略的抓手。约定用词（自由文本亦可，但下列词被 `prune` 特判）：

| 层级 | 常用标记 | 压缩含义 |
|---|---|---|
| 事物 | `已结` | `prune --collapse-done` 会折叠其要求层 |
| 目的 | `待办` / `进行中` / `已完成` | 供 `read --level 2` 时目视筛选 |
| 要求 | `约束` / `偏好` | 硬性约束优先保留，偏好先被预算裁掉 |
| 要求 | `已废` | `prune --drop-stale` 会删除 |
| 要求 | `待补` | 表示原话里数字缺失，**是占位而非事实**，禁止补造 |
| 要求 | `钉住` / `长期` / `暂态` | **生命周期标记**，供 `prune --aging` 判定，见下节 |

### 五之二、生命周期保留标记

`钉住` / `长期` / `暂态` 三个词被 `prune --aging` 特判（未打标记的条目**默认保留，永不被自动动过**）：

| 标记 | 老化后的动作 | 语义 |
|---|---|---|
| `钉住` | **永不自动老化** | 用户明确要求长期记住的内容，优先级最高 |
| `长期` | 不删，但列为**升格候选**并输出到 `--emit-promote` 文件 | 超出当前作用域寿命，看起来值得在更持久的作用域里生效 |
| `暂态` | 超过 `--days` 阈值即**折叠**（删除该条） | 用完即弃的中间结论 |

> 判定是「标记 × 年龄」二维，**年龄来自 `--today` 与头部日期之差，必须显式给 `--today`**，否则同一命令不同天跑出不同结果。完整语义与升格判据见 `references/lifecycle.md`。

## 五之三、作用域（scope，可选的自描述字段）

`scope:` 声明这份存储的**作用半径**——「这条内容该在多大的范围里生效」。它不改 `.ctx` 的行语法，只是头部多一个可选段。

| 取值 | 作用半径 | 典型载体 |
|---|---|---|
| `user` | 跨项目：用户级长期偏好、个人习惯 | 用户级 `MEMORY.md` |
| `proj` | 跨会话：当前工作区的约定、架构决策 | 工作区 `MEMORY.md` |
| `task` | 本次会话：临时方案、待办 | 工作区日志 `YYYY-MM-DD.md` 或临时库 |
| `user:name` / `proj:name` / `task:name` | 限定名，用于同名多实例 | 如 `proj:demo`、`task:2026-10-15-brand` |

约束：

- 未声明 = `None`，**不做任何推断**（兼容 v1.0.x 旧文件，旧文件一律视为「未声明」）。
- `user` / `proj` / `task` 之外的种类，或限定名里出现 `user/proj/task` 以外的字符集（只允许字母数字与 `_ . -`），一律 `EXIT 1`。
- 目录暗示与头部声明不一致时（如文件放在 `user/` 下但头部写 `scope:proj`），**只报 `mismatch` 提示、不报错**——目录约定属于宿主适配层，内核不强制。
- 分区靠**目录**表达（`user/`、`proj/<name>/`、`task/<id>/`），`scope:` 字段是**自描述与交叉校验**用的，不是分区的唯一依据。

> **行尾 ` [xxx]` 一律解释为标记。** 若名称本身要以方括号结尾，请改用全角 `［］`。

## 六、不变量（`ctx.py validate` 逐条强制）

解析器把下列每条都做成一条独立规则，违反即 `EXIT 1` 并给出**带行号的中文定位**：

| # | 不变量 | 抓的坏法 |
|---|---|---|
| V1 | 第一个非注释行必须是格式正确的 `#CTX` 头部 | 头部缺失 / 格式写坏 |
| V2 | 格式版本必须是 `1` | 版本不受支持 |
| V3 | 不出现空行 | 结构被隔断 |
| V4 | 缩进只能是 0 / 2 / 4 格 | 缩进错位 |
| V5 | 缩进 2 格的行必须匹配目的行语法 | 层级写错 |
| V6 | 缩进 4 格的行必须匹配要求行语法 | 层级写错 |
| V7 | 目的行之前必须已出现事物行 | 层级跳跃 |
| V8 | 要求行之前必须已出现目的行 | 层级跳跃 |
| V9 | 事物编号唯一、目的编号唯一 | 编号重复 |
| V10 | 名称非空；名称 ≤200 字符（`top:` 行 ≤500 字符） | 空名称 / 超长 |
| V11 | 名称不含控制字符（含制表符）与 U+FFFD | 制表符污染 / 编码损坏 |
| V12 | 名称不含半角方括号 | 与行尾标记语法冲突（`R z [约束` 这类写坏的标记） |
| V13 | 头部计数与实际节点数逐项相符 | 手改后计数失真 |
| V14 | 至少存在一个事物节点 | 空壳存储 |
| V15 | 头部 `scope:` 段（若有）必须是合法作用域 | 作用域拼错 / 种类不存在 |
| V16 | 缩进 4 格的行必须匹配**要求行或事件行**语法 | 行类型写坏 / 未知行首标记 |
| V17 | 有事件行时头部必须声明 `\| E<n>`，且计数与实际事件行数相符 | 事件节点未声明 / 计数失真 |
| V18 | 事件行摘要非空、非纯空白、不含半角竖线、≤200 字符、不含方括号 | 空摘要 / 分隔符冲突 |
| V19 | 事件行 `bytes` 为非负十进制整数、`sha256` 为 16 位小写十六进制 | 指纹写坏 |
| V20 | 事件行之前必须已出现目的行（与 `R` 同级，不得直接挂在事物下） | 层级跳跃 |

`V13` 是这套格式的**自校验核心**：任何外部手改都会在计数上留下痕迹。
`V12` 是一条**歧义消除规则**：行尾 ` [xxx]` 是标记语法，因此名称里若出现半角方括号就无法判定意图——一律拒绝，需要方括号请用全角 `［］`。
`V15` 保证作用域是**封闭枚举**：写错成 `scpoe`、`project`、`用户级` 都会被当场拒绝，而不是被当成一个未知的合法值悄悄写进文件。
`V17` 是 `V13` 在事件节点上的延伸：**`E` 计数是独立一项，不与 `R` 混计** —— 所以「把事件行当成多出来的一条要求」这种手改会被立刻抓到。
`V18` 与 `V12` 同源：半角竖线是 `E` 行元信息的分隔符，摘要里出现它会把元信息切错位，因此与方括号一样**一律改用全角**。

## 七、跨库索引格式（`index` 子命令输出）

索引**只索引键层**（事物名与目的名）与**事件节点行**，不含任何要求行的内容 —— 因此它的体积与实际**内容量**无关。索引是**导航，不是真相**：任何内容以各 `.ctx` 库为准，索引与库不一致时以库为准并重建。

```
#IDX 1 | 2026-10-15 | stores 2 | T3 P3
S user | proj/wrong.ctx | rev 0 | date 2026-10-15 | T1 P1 | mismatch
  T1 放错地方的库
    P1.1 举例
S user | user/u.ctx | rev 0 | date 2026-10-15 | T1 P1
  T1 称呼与语气
    P1.1 语言风格
      E 旧版内核实现 | src:src/kernel.py | bytes:90554 | sha256:3f6ed874c97053c2
```

| 行 | 形态 | 含义 |
|---|---|---|
| 头 | `#IDX 1 \| 日期 \| stores N \| Tx Py` | 版本 / 生成日期 / 库数 / 键层节点数 |
| 库 | `S <scope或-> \| <相对路径> \| rev N \| date … \| Tx Py [\| mismatch]` | 一个库的键层摘要 |
| 事物 | `  T<n> <名称>` | 缩进 2，与 `.ctx` 同款语义 |
| 目的 | `    P<n>.<m> <名称>` | 缩进 4 |
| 事件 | `      E <摘要> \| src:<路径> \| bytes:<字节数> \| sha256:<16 位>` | 缩进 6；**只有摘要与指针，没有正文** |

> **一个必须点明的例外**：索引体积对**内容量**不敏感，但 `E` 行会带上**完整指针与指纹**，
> 所以索引会随「事件节点数 × 指针路径长度」增长，**并非完全不涨**。
> 这是刻意的取舍：原文不进库时，指针是唯一的抓手 —— 不带它，索引就回答不了
> 「哪一块是要逐字操作的、它现在还在不在」。换句话说，**导航层的厚度取决于你把索引做到多细，这是一个取舍而不是定值**。

索引的**确定性**要求：

- 排序固定为「作用域持久度（user→proj→task→未声明） → 限定名 → 相对路径」，全程不依赖 `os.walk` 顺序。
- 坏库（无法解析）**只跳过并报到 stderr**，不中断整次扫描、不影响退出码，也不进入索引体。
- 无变化时**不写盘**（与 `add` / `prune` 同一原则）。

## 八、已知取舍（诚实声明）

1. **不是 JSON**：外部工具需先 `export --format json`。这是为模型阅读的 token 效率付出的代价。
2. **`//` 注释会被计入文件体积**，但不参与计数；`prune --compact` 会清除它们。文件开头的 `//` 横幅是允许的（头部取第一个非注释行）。
3. **`top:` 行有独立长度上限 500 字符**（会话总目标可能较长），节点名称上限仍是 200 字符。
4. **要求节点无独立编号**，因此「第 3 条要求」这类引用在插入后会漂移；需要稳定引用时请用 `export --format json` 取结构。
5. **没有环检测**：缩进树天然无环，只可能断裂，断裂由 V7/V8 抓。
6. **`prune --collapse-done` 保留键位**：它清空已结事物的要求层，但 T 行与 P 行都留着（`[已结·已折叠]`），因此折叠后仍能看出「这件事做过」。
7. **`--budget` 是软上限**：key 层（头部 + T + P）永不裁剪，key 层自身超预算时输出会略超预算；`--budget` **不接受负数**（负数会被拒绝而不是被忽略）。
8. **无实际改动就不写盘**：`add` 遇到纯重复增量、`prune` 遇到无可折叠内容时，**不写文件、不递增 `rev`**，输出里明确写「内容未变化，未写盘」。因此 `rev` 严格等于「真正发生过的内容修改次数」。
9. **没有文件锁（已知限制）**：两个进程同时写同一个 `.ctx` 是「读-改-写」竞态，**并发写不保证合并**，可能丢更新。写入用同目录临时文件 + `os.replace` 替换，所以**不会读到半成品**。临时文件名为 `路径.<pid>.<线程号>.tmp`——**必须唯一**，因为 Windows 的 `os.replace` 语义是「先删目标、再搬源」，共用固定临时名会让后写者删掉前写者刚放好的目标却搬不回源文件，导致**目标文件凭空消失**。唯一临时名保证最坏情况只是丢更新，绝不丢文件。本技能的预期用法是单智能体串行写入，请勿并行写同一文件。
10. **名称归一化只做空白折叠**：连续空白折叠成一个空格、首尾去空白；**不做 Unicode 归一化**，因此全角/半角字母或异体字会被视为不同键（如 `ＡＢ` 与 `AB`）。需要严格判等时请人工统一写法。
11. **作用域是自描述、非强制**：内核不因为 `scope:` 就改变任何读写行为，只是把它当作元数据保留与校验。分区的实际意义由宿主适配层赋予（见 `host-memory-adapter.md`），换一个宿主环境时语义可能不同。
12. **作用域判错无法被内核发现**：把一条团队规范写成 `scope:task` 在格式上完全合法——内核只能保证「值是合法枚举」，不能保证「值判得对」。域判错的危害是**记忆污染**（错误的结论在错误的范围里生效），比记漏更糟，因此默认策略是**宁可窄不可宽**：拿不准就写 `task`。
13. **索引会随库变化而漂移**：索引是某一时刻的快照，之后任何库发生修改都不会自动更新索引。**索引缺失或过期时，逐库扫描仍应完全可用**，索引只是加速与导航，不是主干硬依赖。
14. **事件节点让库不再自包含（默认如此）**：库里只存指针，原文留原处。原文件被移走或删除后报 `MISS`，**内容拿不回来**。要自包含就用 `--embed`，代价是库体涨回原文大小——等于把压缩收益还回去。这是有意识的默认：**库应当轻，原文应当只有一个出处**。
15. **`STALE-SRC` 不改变退出码**：取回内容可信但指针已失效时只提示。理由：若把指针失效也算失败，那么「内嵌副本 + 原文件被正常编辑」这种常见情形会到处报错，反而促使使用者去关掉校验。**内容校验必须硬、指针状态必须软**，两者不能混成一条。
16. **未知叶子种类直接报错，不默认当 R**：内核用显式白名单（`LEAF_KINDS`）分派叶子。将来新增行类型必须同步登记，否则第一次渲染/计数就会失败。**这是刻意的** —— 「缺省当 R」会让新类型被静默降级（改它的内容被判 no-op、折叠时被删掉，且一个错误都不报）。
17. **事件节点不参与 `--budget` 裁剪与自动老化**：预算裁剪只裁 `R` 行；`prune --aging` / `--collapse-done` 不动 `E`。理由是原文不可再生。唯一能删的路径是**显式**标 `[已废]` 后走 `--drop-stale`。
18. **块级门控不需要预估复用次数**：因为建库那次读取**不额外付费**（原文本来就要读），把原料读取成本从决策里删掉后，块级断点从 `k > (1+r)/(1−r)` 降到 `k > 1/(1−r)`，规则退化为「**读过的块就压存**」。**一个需要预测的参数，最好的处理方式是让它消失。**
